## Requirements

Nest Graph Inspector is built for modern NestJS applications and reads from the runtime Nest container after your app has initialized.

| Requirement | Version |
| ----------- | ------- |
| Node.js | 20 or later |
| NestJS | 10 - 11 (NestJS 12 is not supported yet) |

::callout{icon="i-lucide-lightbulb" color="neutral"}
Earlier NestJS versions may still work, but they are not officially supported. You can try force installing:

::package-manager-command{command="force-install"}
::

If it works for your project, [raise an issue](https://github.com/albasyir/nest-graph-inspector/issues) so support coverage can be updated.
::

## Graph export

[`nest-graph-inspector export`](/getting-started/export-graph) loads the file that exports your root module — compiled, or its TypeScript source through a `--require` loader:

- **A bundle that starts the app is never loaded.** A webpack or rspack build — what `nest g app` sets up when it turns a project into a monorepo, writing `"builder": "rspack"` into `nest-cli.json` (older Nest CLIs wrote `"webpack": true`) — bundles everything into one `main.js` that calls `bootstrap()` when loaded, so the export refuses it. No `--entry` is needed, though: the export [finds your root module from `main.ts`](/getting-started/export-graph#how-the-root-module-is-found) and loads its TypeScript source given `--require ts-node/register`, plus `--require tsconfig-paths/register` for path aliases ([TypeScript, without building](/getting-started/export-graph#typescript-without-building)); without them, it prints the exact command to run. For compiled files instead, build with `"builder": "tsc"` and without `"webpack": true`; a `nest-cli.json` that names no builder, monorepo or not, is built with `tsc`, as the Nest CLI builds it.
- **ES modules** — `.mjs` and `.mts` files, and `.js` files whose nearest package.json says `"type": "module"` — are loaded with `import()`; everything else, even `.ts` in such a package, with `require()`. `ts-node/register` only handles CommonJS, so build an ESM project written in TypeScript first.

## Browser

Any current browser can open the graph viewer. The AI chat is the one part that asks for more, because it runs its model on your own machine instead of on a server.

| Viewer feature | Browser requirement |
| -------------- | ------------------- |
| Graph, issue finder, Direct Run | Any current browser |
| AI chat | A desktop browser window at least 768px wide, with WebGPU — Chrome or Edge 113+, Safari 18+, or Firefox with WebGPU available |

The chat checks for WebGPU as soon as you open it, before you ask it anything, and says what is missing rather than failing mid-answer. Nothing else in the viewer depends on it, so a browser without WebGPU still shows the whole graph.

Choosing a model downloads it the first time. The browser caches it, so that cost is paid once per model and later sessions start with it already in place.

The model also has to fit in your GPU's memory while it answers. The six general models on offer need roughly 0.9 GB to 3.7 GB of VRAM, and the two tool-tuned Hermes builds need 3.9 GB and 4.8 GB. Each one says how much next to its name — a model that does not fit will download and then fail to load, so pick one your GPU has room for.
